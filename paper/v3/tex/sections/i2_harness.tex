\section{The harness program: changes, gates and runs}\label{app:harness}

This appendix holds what Sec.~\ref{sec:harness} leaves out: each change as built, each predeclared gate, and every run read. The changes are overlays that the notebook builder applies as asserted string edits (\texttt{solution/kaggle/franzen\_overlays/}: \texttt{unstick2.py}, \texttt{seg8.py}, \texttt{scroll.py}, \texttt{tool2.py}, \texttt{verify.py}); the gates are the files \texttt{solution/kaggle/generated/gate-predeclared-2026-10-30-*}, \texttt{-2026-10-31-*} and \texttt{-2026-11-01-*}, each written before the first run of its build. The per-run tables are rebuilt by \texttt{paper/v3/analysis/harness\_read.py}, except the six rows of the tool-fix and replay builds, which come from the gate readers; the gate readers and record writers are in \texttt{solution/analysis/harness\_2026-10/gates/}. % V3-W19 V3-W20 V3-W22 V3-W23 V3-W28 V3-W29

\subsection{The changes as built}

\paragraph{Stall check, coverage and step checking.}
Four parts. % V3-W20
(1) A stall check at the third, fifth, seventh and later idle turn on a level asks the model to call \texttt{action()} before any long search, and says that a filler key press or a RESET wastes actions.
(2) After a stall check, a game over or a model RESET on the level, the opener lists the object types (colour and bounding-box size, joined by corner contacts, dot textures left out) that no click on the level has touched, when a click is a valid action, and the valid actions unused on the level; engine action names (\texttt{ACTION1} to \texttt{ACTION7}) are mapped to the history's names first, and UNDO is dropped.
(3) On the first opener of each level after the first, the opener lists the object types new on that level, same colour and box merged.
(4) Tufa's step-verification addendum, off in Franzen's settings, is on: mechanics first and goal last, replay the level's recorded transitions through a simulator before a long plan, and retry a no-op from another state before ruling it out.
On frames replayed through the real patched helpers, the coverage list costs about 6 ms per call and the new-type list about 175 ms per level start. % V3-W20
The offline test feeds engine action names and fails on the first build.

\paragraph{Corner-joined regions.}
Every node of the segmentation gains \texttt{group}, the lowest node id among nodes of the same colour joined to it through corner contacts, one 8-connected object; ids, hashes, boundaries and adjacency are unchanged, the node line of the system prompt names the field, and the module is spliced into the sandbox so both views carry it. % V3-W22
The offline test shows that groups equal the 8-connected objects on a synthetic board and on all 184 human level starts. % V3-W22
A start holds such an object when a group of two or more nodes has a bounding box of at least 3 by 3 cells: 76 of the 184 starts, in 13 of the 22 replayed games, do (73 with sparse dot lattices, fill under 0.1, dropped). The gate record's earlier count, 71 starts in 13 of 21 games under a dot-texture rule it does not state, is not reproduced and is not used. % V3-W22

\paragraph{Scroll.}
The diff tool detects a whole-interior shift along one axis: a 4-cell edge band is left out, candidates come from whole-line matches, and a shift is accepted at a cell mismatch rate of at most 0.1 and at most 0.3 of the unshifted rate over at least 60 changed cells. % V3-W23
It shifts the earlier frame and its objects by the shift, adds \texttt{scroll: [rows, cols]} to the output (unchanged when nothing scrolls), and the turn opener says when the last sequence of frames scrolled and by how much. % V3-W23
The offline test covers a synthetic scroll, a plain move that stays unchanged, the sandbox copy, the opener line and every human-replay frame pair. % V3-W23
In the 22 human-replay games it fires on 103 of 363 changed pairs in bp35, on 40 of 772 in lf52, and on none of the 5,178 in the other 20 games (6,170 silent pairs in all); a synthetic scroll leaves the player and the status bar as the only changes, where the unpatched diff reports 76 moved objects. % V3-W23

\paragraph{Tool fixes.}
In the sandbox child a timer on the snippet's own compute (time spent waiting on the host for an action or animation reply is not counted, and a timer that fires during such a wait is deferred, so a reply is never cut) raises \texttt{SnippetTimeout} at the compute limit minus 3 seconds; it derives from \texttt{BaseException} so an \texttt{except Exception} clause in model code does not swallow it (a bare \texttt{except} that does is stopped again a second later), and the child returns the printed output, the traceback line and the retained functions instead of the host's empty ``Tool timed out''. % V3-W28
\texttt{inspect.getsource} is patched to return the stored source of a function retained from an earlier snippet or defined in the current one. The system prompt says both. % V3-W28
The offline test runs the real child: a loop stops at 3.1 seconds of a 6-second limit with its output kept (unpatched: timed out at 6.0 seconds, empty output), a swallowed first stop is stopped by the second, and a 3-second host reply against a 1-second compute limit is never cut. A loop that swallows \texttt{BaseException} every time is not stoppable by the child; the host's hard deadline still applies. % V3-W28

\paragraph{Replay check.}
Two helpers in the sandbox. \texttt{check\_model(step, observe=None)} takes the model's own transition function and, when \texttt{observe} is given, a map from a recorded frame to the model's state (or \texttt{step} takes the frame itself and returns its board text or a dict of cells; \texttt{None} abstains). It replays the current level's recorded transitions newest first, skipping RESET, automatic RESET, death and level-change steps, and prints the first three mismatches with predicted and actual state (an exception raised by the model's code counts as a mismatch), plus a count of board and action pairs seen twice with different results (hidden state: a counter, timer or facing). % V3-W29
\texttt{check\_goal(is\_goal)} runs a goal test on every recorded board of the level and returns the indices where it is true; the printed note says a hit means the test is wrong or incomplete, or that board needed one more action, since the winning board itself is never recorded. % V3-W29
\texttt{action()} is disabled during both, model exceptions are caught and reported, output is capped at 1,400 characters, and each call checks its clock between transitions and stops after 8 seconds, or 2 seconds before the snippet's own tool-fix stop if that is sooner; a single slow step is not interrupted. The system prompt documents both with a one-line adapter, and the stall check and the turn opener name them. The overlay is applied after every other one so its prompt edits find their anchors. % V3-W29
The offline test runs nine checks through the real child on both bases (with and without the tool fixes): a correct rule matches every level-2 transition with RESET and death skips counted, a wrong rule names the newest mismatch, a rule that calls \texttt{action()} is refused and no action runs, a slow rule stops at the limit before the snippet's own stop, and an ordinary snippet is unchanged. % V3-W29

\paragraph{Readings declared and not computed.}
The replay gate also listed readings to report but not gate on: levels on a window aligned to server readiness, and whether a mismatch was followed by a redefined rule within two turns. Neither was computed for this paper. % V3-W29

\paragraph{A start-time confound.}
Franzen's notebook starts play when the server reports ready, or at a deadline about 720 seconds after the notebook starts with the server still loading; games released at the deadline wait on a server that cannot answer while their clock runs. % V3-W32
Of 23 Kaggle replica runs of the 15-stream family, 13 were released at the deadline and 6 started 12 to 21 minutes before the server was ready: one of the two Kaggle control runs, one of three stall check runs, two of three corner-joined runs, one of three scroll runs, one of three tool-fix runs and none of the three replay-check runs, whose latest start was one minute early; the five Vertex control runs were not read. % V3-W32
The offset therefore sits unevenly in the arms; it could flatter the replay build against the others and understate the corner-joined build, and we did not estimate its size. % V3-W32

\subsection{Earlier arms on the same agent}

Two earlier arms ran on the 15-stream build in the same weeks and are not part of the program. A kept-variables overlay (plain data kept for the length of a level so the model does not rebuild it after each action) was built to halve NameErrors per python call; two versions read 0.51 and 0.52 against a bar of 0.50, were killed by their own rule and did not move levels (pooled 127.8 and 125.3 against 125.7 and 123.4). % V3-W26
A shorter-thinking model (ThinkingCap) cleared 122 levels against 129 for the build beside it on Kaggle and took 70\% more actions, so its game score fell 15\%; it was killed, and its Vertex wave was cancelled. % V3-W26

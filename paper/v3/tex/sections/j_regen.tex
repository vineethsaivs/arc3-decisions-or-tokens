\section{Regeneration and compute}\label{app:regen}

\subsection{Scripts from the v2 analysis}

Most claims in Appendix~\ref{app:claims} come from a script in \texttt{paper/v2/analysis/} that reads recorded runs and writes small text or JSON files; none starts a run or needs a GPU. Seven are read from records or source code instead: A3, D14, E1, E9, F1, F2 and F3 (the time ledger re-derives part of F1). % A3 D14 E1 E9 F1 F2 F3
Table~\ref{tab:regen} lists each script, its output, the claim ids it produces and its runtime. Scripts run on one CPU core with the Python standard library and no network unless marked. The three new analyses and the plateau figure also import the repository's simulator (\texttt{scheduler\_sim.py}, through \texttt{e5\_lib.py}) and read the recorded runs.
The only cost is the development run itself: about 2 h 10 min and \$4 per 25-game run on the earlier rented VM with the same card (Sec.~\ref{app:compute} has current rates). % NEW:cost H1
The leaderboard score cannot be regenerated; it is verified by submission ID (Sec.~\ref{sec:board}). % G7 V3-B2
